SCREENATOR WINDOWS - UPDATE FROM 7.0 TO LINUX 8.0 BEHAVIOUR
============================================================

Purpose
-------
This file is a self-contained implementation brief for a DeepSeek V4.1 Flash
session working on the native Windows Screenator repository.

The Windows port is currently at 7.0.  The Linux application has advanced to
8.0.  This brief describes every Linux 7.0 -> 8.0 change, states which changes
apply to Windows, and gives a safe implementation order, edge cases and
verification steps.

Do not copy GTK, X11, GDK, Wayland, AppIndicator or other Linux-only code into
the Windows port.  Adapt behaviour to native Win32/Cairo/Pango.

Target directory
----------------
screenator-windows/

Source of truth
---------------
This file, plus the existing Windows sources and documentation.  The Linux
release notes are summarised here; the Linux source tree is not required to
start the work.

Version rule
------------
Keep the Windows version at 7.0 until the user explicitly asks to release.
Do not commit, tag, push or publish a GitHub release unless explicitly asked.


HOW TO USE THIS FILE
--------------------
1. Read the whole file before editing code.
2. Start with Part 1 (audit).  Do not implement anything during the audit.
3. Implement Part 2 work items in the stated order, one item at a time.
4. Build and run the available tests after every work item.
5. Do not start Part 3 (optional major features) without explicit approval.
6. Finish with Part 4 and Part 5.
7. Report exactly what changed, what was skipped and what still needs manual
   testing.

If a requirement has no reasonable Win32 equivalent, mark it "not applicable"
in screenator-windows/PORTING_STATUS.md.  Do not invent a fake subsystem just
to make the Linux behaviour appear implemented.

WORK ITEM 1 - BUNDLED HTML HINTS, CSS COLOURS, SIZE, ABOUT
------------------------------------------------------------

Current Windows files to inspect:
- src/ui.c: hints_rtf(), hints_proc(), ui_show_hints(), CMD_SHOW_HINTS,
  run_modal(), center_window(), HINTS_CLASS;
- build.bat and build.sh packaging lists;
- assets/icons.

Goal:
Match the Linux 8.0 hints experience using native Win32 controls and the
existing RichEdit/RTF presentation.  Do not add a browser or WebView.

Required behaviour:

1. Load the hints from the bundled file `assets/hints.html`.  There is no
   per-user override and no SCREENATOR_HINTS_FILE environment override.
   Load the file fresh every time the hints dialog opens.

2. Supported HTML subset:
   h1, h2, h3, p, ul, ol, li, br, b, strong, i, em, u, tt, code, a, span,
   font.

   Support:
   - inline style="color:#rrggbb";
   - simple CSS rules in a <style> block for simple tag selectors, for
     example:
         h1 { color: #000000; }
         h2 { color: #008800; }
         span { color: #0000aa; }
   - inline colour wins over the stylesheet.

3. A malformed bundled file must not blank the hints window:
   - ignore an extra closing tag;
   - keep the result valid when tags are crossed;
   - auto-close any tag left open;
   - fall back to built-in safe text if the file is missing or unreadable.

4. Make the hints window exactly 700x500 in the primary monitor work area.
   Centre it once when it opens.  Do not repeatedly resize or recentre it.

5. Add a native caption/title bar ("Screenator Hints"), a close button and a
   visible border.  Keep the existing "Never show hints again" checkbox.

6. Add an About button immediately before Close.  It must open the normal
   About dialog and return to the hints dialog.

7. Keep Show Hints available from the tray menu and add it to the quick menu
   after Settings if the quick menu has a Settings entry.

8. Update the hints text to Linux 8.0 wording:
   - right click / stylus Button 2 accepts text like Enter;
   - F4 takes a screenshot in both Screen and Paper modes;
   - selecting a Paper tool brings the Paper window to the front;
   - the stylus first side button temporarily erases unless handles are active;
   - headings and spans support colours.

Acceptance checks:
- verify the bundled hints render on every open;
- test a malformed copy without creating a user override;
- check the exact 700x500 size and one-time centring;
- open About and return;
- package includes assets/hints.html and the hint icon;
- --uitest and --smoke pass.

WORK ITEM 3 - CURSOR TOOL, TOOL EXIT, TEXT COMMIT AND PAPER FRONT
-----------------------------------------------------------------

Inspect:
- Tool enum and state in src/app.h;
- tools_activate / tools_request / tools_exit / tools_commit in src/tools.c;
- Escape, right-button and handle code in src/main.c and src/tools.c;
- menu checkmarks in src/ui.c;
- text editor state and commit/cancel handlers;
- paper window show/focus code;
- WM_DISPLAYCHANGE and DPI handling.

Required behaviour:

1. Add a Cursor tool if there is none:
   - no drawing tool active;
   - normal arrow cursor;
   - clicking does not draw;
   - available in Screen and Paper modes;
   - visible and active in the tool menu and quick menu.
   Reuse the Linux cursor.png asset if it is available in the Windows repo.
   Otherwise use an existing suitable cursor icon; do not reference a missing
   file.

2. On startup, no drawing tool is active.  Cursor is the active tool even if
   a tool was selected when the application last exited.

3. First Escape or right click while a shape/text/spline/polygon/triangle/
   line still has handles or an unfinished edit:
   - commit/close the handles;
   - keep the selected tool active;
   - consume the event and return handled.

   A further Escape exits the tool and selects Cursor.

4. Right click, stylus Button 2 or mouse button 2 while the inline text editor
   is open must act like Enter:
   - commit the text;
   - re-enable the mouse;
   - keep the new text handles visible in both Screen and Paper modes;
   - consume the press and its release;
   - do not also close the handles;
   - do not start the temporary eraser.

   Escape still cancels text.

5. In Paper mode, selecting any tool must bring the Paper window to the front:
   - deiconify/present it;
   - raise it above other applications;
   - focus it;
   - keep the toolbar and floating controls above it.

5b. Remove the Screen-mode right-click popup menus for colour, thickness,
    marker opacity and similar settings.  A short right click only performs
    Escape/closes handles.

5c. In Screen mode, the stylus first side button and the middle mouse button
    activate the temporary eraser on a normal press, with no long press.
    When a text or shape still shows its handles, the stylus first side button
    changes its colour instead, exactly as in Paper mode.

6. When switching between Screen and Paper modes:
   - commit any text or shape still showing handles;
   - exit the current tool;
   - select Cursor in the new mode;
   - do not reactivate the tool that was used before the switch;
   - the icon and the working tool must agree.

   Switching from one paper type to another, or opening another PDF while
   already in Paper mode, must keep the active tool instead of selecting
   Cursor.  Resetting a paper still exits to Cursor.  Paper type changes and
   PDF opens must bring the Paper window to the front above other
   applications.

7. On WM_DISPLAYCHANGE, DPI change, monitor change or equivalent:
   - exit the current tool;
   - select Cursor;
   - release tool capture;
   - refresh the cursor and menu active state.

8. Preserve the existing captured-menu and delayed-tool behaviour.

9. Timer behaviour:
   - use F12 for the Timer shortcut where Windows can support it;
   - the Timer locks tool selection during the countdown and activates Pen at
     the end;
   - keep existing Windows timer behaviour if F12 is unavailable, but do not
     silently change an unrelated shortcut.

10. Fix cursor/tool mismatches:
    - the normal pointer must not appear while a drawing tool is active;
    - the cursor must follow the actually active tool;
    - the eraser cursor must scale correctly in Window mode;
    - no stale tool cursor after resolution, DPI, mode or document changes.

11. Ctrl/Alt letter shortcuts must work on non-Latin layouts such as Arabic.
    Match physical key positions or Windows virtual-key codes, not the character
    produced by the active layout. This includes Ctrl+D and Ctrl+W.

Acceptance checks:
- text/arrow/line/spline/polygon/triangle/frame handles;
- first Escape closes handles, second exits to Cursor;
- right click/Button 2/mouse button 2 commits text and leaves handles in both
  modes;
- select a tool while Paper is behind another window;
- switch Screen -> Paper and Paper -> Screen; Cursor must be selected;
- select/reset a paper and open a PDF; the Paper window must come to the front;
- change resolution/DPI with a tool active;
- --uitest, --smoke and --pen-test if pen input changed.

Otherwise keep the existing PNG annotation save and undo/redo behaviour, fixing

Additional drawing fixes to port where applicable:

-----------------------------------------------

The Linux 8.0 tool bar includes:
- F10 show/hide;
- horizontal or vertical direction;
- configurable icon size;
- visible icons and order;
- hidden items keep their settings-list position when toggled;
- no button border or gap between adjacent icons;
- the current-page indicator uses the same square size as the icons;
- the thickness icon follows the bar direction: horizontal lines in a vertical
  bar and vertical lines in a horizontal bar;
- one pixel border around the tool bar itself;
- keep the bar flush with its screen edge or centre when its width changes;
- draggable and snapping position;
- anchored tooltips, including for insensitive buttons;
- current-page indicator and Go to Page button;
- actions:
  Switch Mode, Cursor, Pen, Text, Eraser, Arrow, Timer, Shapes, Undo, Redo,
  Save/Screenshot, Paper Type, Insert Page Before, Delete Page, Insert Page
  After, Current Page, Go to Page, Clear Screen, Toggle Visibility, Eraser Size,
  Line Color, Thickness, Fill Color, Opacity, Marker Opacity, Settings,
  Show Hints, Quit.

Implementation notes:
- design the Win32 window/layout and input-capture model;
- reuse existing menu commands and tool activation;
- decide how the bar interacts with screen paper and the floating icon;
- add settings and INI persistence;
- persist the full row order separately from the visible-item list so hiding
  and showing an item never moves its row to the end;
- migrate old saved layouts once when adding new buttons, then respect the
  user's visibility choices on later starts;
- do not duplicate command logic that already exists in menus.

This is a substantial feature.  Produce a design and wait for approval.


OPTIONAL FEATURE B - PAPER/PDF PARITY
-------------------------------------

Linux 8.0 added a full Paper Drawing/PDF subsystem:
- Plain, Ruled, Graph and PDF documents;
- multiple pages with insert/delete and page undo/redo;
- continuous scrolling with a grey gap between pages;
- Page Up/Page Down navigation and Home/End first/last page;
- Go to Page dialog for PDF and multi-page Plain/Ruled/Graph documents;
- current-page indicator before Go to Page;
- per-document pages, drawings, current page, view position and PDF file;
- PDF import/render, page memory and background caching;
- background render worker with a white "Loading..." placeholder and stale-job
  cancellation;
- vector PDF export with text as text and graphics as vector paths;
- save progress overlay, repeated-save guard and Poppler serialisation;
- fullscreen, Ctrl+W resizable Window mode and Ctrl+D panel mode;
- local focus-scoped input with no global pointer grab;
- eraser cursor scaling with the paper in Window mode;
- uniform page scaling and centring on resolution or paper-size changes;
- paper size settings: Screen, A4 portrait, A4 landscape, Custom;
- PDF MIME registration and file-browser handoff;
- each PDF remembers the page it was last closed on;
- opening a PDF through Open With, the desktop entry or a command-line file
  argument starts in Paper mode;
- forwarding a PDF to an already running instance;
- switching paper types keeps each paper's drawings;
- returning to a PDF reuses the already opened PDF;
- Paper menu "Reset/Open PDF..." resets a Plain/Ruled/Graph paper to one empty
  page, or opens another PDF when the current paper is PDF, asking to save
  unsaved changes first;
- Save writes to the user's Documents folder using
  Screenator-plain-YYYYMMDD-HHMMSS.pdf, Screenator-ruled-..., Screenator-graph-...
  or Screenator-file-... for opened PDF files, adding a numeric suffix if the
  name already exists;
- only changed papers are written;
- exit offers to save every changed paper, ignore changes or cancel;
- vector-only export: no bitmap fallback for annotations or backgrounds;
- an eraser stroke over empty space leaves the vector layer untouched;
- when an eraser removes ink, keep the remaining drawing vector and text as
  text, baking only an alpha mask into the affected layer;
- paint-bucket fills stay screen-only and are not exported.

Before coding, produce a design covering:
- PDF engine choice (Windows.Data.Pdf, PDFium, MuPDF or another compatible
  option);
- page model and cache limits;
- Win32 window/focus/input model;
- vector export using Cairo PDF;
- UI for pages, paper types and tool bar;
- packaging and licence implications.

Do not write implementation code until the user approves the design and
dependencies.  If not approved, mark the whole item deferred.

F. Saving and PDF export (Windows: conditional/optional)
--------------------------------------------------------

  Screenator-plain-YYYYMMDD-HHMMSS.pdf
  Screenator-ruled-YYYYMMDD-HHMMSS.pdf
  Screenator-graph-YYYYMMDD-HHMMSS.pdf
  Screenator-file-YYYYMMDD-HHMMSS.pdf for opened PDF files
- Save button and Ctrl+S save only the current paper.
- Only changed papers are written.
- Success dialog shows saved path(s).
- No changes shows a "no changes to save" message.
- Save confirmation appears only when exiting.
- Exit dialog offers save all, ignore or cancel.
- Exit save lists all created files.
- Per-paper modified tracking.
- PDF export embeds original PDF page as vector content.
- Plain/Ruled/Graph backgrounds exported as vector.
- Strokes, lines, arrows, frames, stars, triangles and splines recorded as
  vector operations.
- Text recorded through Pango and exported as text.
- PDF export is vector-only; annotations never written from the raster layer.
- Paint-bucket fills are screen-only and not exported; they do not force the
  page to bitmap.
- Undo/redo keeps a parallel vector snapshot.
- New PDF pages start vector recording before first background render; the
  recording is scaled to the final page size.
- Transparent pen/marker strokes are one continuous vector path.
- Saving preserves original PDF vector content and overlays annotations.

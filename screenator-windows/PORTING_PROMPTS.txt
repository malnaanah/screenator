SCREENATOR WINDOWS PORT - PROMPT PACK
=====================================

Target: screenator-windows/ (native Win32 port)
Linux source version: Screenator 8.0 (commit f41a45e and later)
Windows version: still 7.0 unless the user explicitly asks to release
Source of truth: release-notes-8.0.md plus the Linux sources under
screenator-linux/ for behavioural reference only.

This file is a sequence of copy-paste prompts for a DeepSeek V4.1 Flash
session running on Windows.  It is deliberately organized into small steps so
each change can be built and tested before moving on.

HOW TO USE
----------
1. Start a new session with the repository root as the working directory.
2. Paste Prompt 0 first.  Do not edit code until its audit is complete.
3. Paste Prompts 1-7 in order, one at a time.
4. Use Prompt 8 or 9 only if the user explicitly asks for that major feature.
5. Finish with Prompt 10.
6. Build and test after every prompt.
7. Do not commit, tag, push or release unless the user explicitly asks.

GLOBAL RULES FOR EVERY PROMPT
-----------------------------
- Read the existing Windows code before editing.
- The Windows port is independent Win32/Cairo/Pango code.  Never copy GTK,
  X11, GDK, Wayland, AppIndicator or other Linux-only code into it.
- Adapt behaviour to Win32.  If a Linux feature has no Windows equivalent,
  record it as not applicable in screenator-windows/PORTING_STATUS.md instead
  of inventing an incompatible subsystem.
- Keep changes small and match the existing Windows naming and style.
- Preserve existing Windows behaviour unless a prompt explicitly replaces it.
- Keep the Windows version at 7.0 unless the user asks to release.
- Build with screenator-windows/build.bat from an MSYS2 MinGW64 shell, or
  ./build.sh from that shell.
- Run the available checks:
      Screenator.exe --selftest
      Screenator.exe --uitest
      Screenator.exe --smoke
  Run --pen-test only when pen input changed.
- Update screenator-windows/README.md and RELEASE_NOTES.md for user-visible
  behaviour.
- Update screenator-windows/PORTING_STATUS.md after every prompt.
- Fix every new warning or error.  Do not silence warnings.
- Report what changed, what was skipped or deferred, what still needs manual
  testing, and the exact build/test result.

IMPORTANT SCOPE NOTE
--------------------
Screenator 8.0 added a full Linux Paper Drawing/PDF subsystem.  The current
Windows port has only screen paper (plain/ruled/graph), a tray menu, a quick
tool menu and PNG annotation persistence.  It does not have Linux Paper pages,
PDF import/export or a persistent Linux-style tool bar.

Prompts 1-7 cover the parts with a real Windows equivalent.  Prompts 8 and 9
are optional major features and must not be started without explicit approval.
Do not fake a tool bar or PDF engine just to match Linux.

PROMPT 1 - HINTS DIALOG: EDITABLE HTML, CSS COLOURS, SIZE, ABOUT
---------------------------------------------------------------
Goal: make the Windows hints dialog match the Linux 8.0 hints experience
using native Win32 controls.

Current files:
- src/ui.c: hints_rtf(), hints_proc(), ui_show_hints(), CMD_SHOW_HINTS,
  run_modal(), center_window(), HINTS_CLASS.
- assets/icons and the build packaging lists.

Required behaviour:
1. Add an editable hints file:
   - assets/hints.html in the packaged data folder;
   - a user override at %APPDATA%\Screenator\hints.html;
   - support SCREENATOR_HINTS_FILE for an alternative file.
2. Load the file fresh every time the hints dialog opens.
3. On first use, if the user file does not exist, copy the bundled/installed
   hints into the user path.  From then on the user file is the canonical
   editable copy.
4. Show the loaded user path in a small footer inside the hints dialog.
5. Supported HTML subset:
   h1, h2, h3, p, ul, ol, li, br, b, strong, i, em, u, tt, code, a, span,
   font.
   Support inline style="color:#rrggbb" and simple CSS rules in a <style>
   block for simple tag selectors, for example:
       h1 { color: #000000; }
       h2 { color: #008800; }
       span { color: #0000aa; }
   Inline colour wins over the stylesheet.
6. Hand-edited files may be malformed.  The converter must:
   - ignore an extra closing tag;
   - keep the result valid when tags are crossed;
   - auto-close any tag left open;
   - never leave the whole hints window blank because of one typo.
   Convert to the existing RichEdit/RTF presentation; do not add a browser or
   WebView dependency.
7. Provide a safe built-in fallback if the file is missing or unreadable and
   show the expected paths.
8. Make the hints window exactly 700x500 on the primary monitor work area.
   Centre it once when it opens.  Do not repeatedly resize or recentre it.
9. Add a native caption/title bar ("Screenator Hints"), close button and
   visible border.  Keep the "Never show hints again" checkbox.
10. Add an About button immediately before Close.  It must open the normal
    About dialog and return to the hints dialog.
11. Keep Show Hints available from the tray menu and add it to the quick menu
    after Settings if the quick menu has a Settings entry.

User-visible text must match the Linux 8.0 wording:
- right click/Button 2 accepts text like Enter;
- F4 works in both modes;
- Paper tool selection brings Paper to the front;
- full colour support for headings and spans.

Verification:
- edit the user file and reopen hints;
- test a file with an unmatched tag;
- check exact size and centring;
- open About and return;
- package includes assets/hints.html and hint.png;
- --uitest and --smoke.

PROMPT 3 - CURSOR, TOOL EXIT, TEXT COMMIT AND PAPER FRONT
--------------------------------------------------------
Goal: match the Linux 8.0 input behaviour in the Win32 port.

Inspect:
- Tool enum/state in src/app.h;
- tools_activate/tools_request/tools_exit/tools_commit in src/tools.c;
- Escape/right-button/handle code in src/main.c and src/tools.c;
- menu checkmarks in src/ui.c;
- text editor state and commit/cancel handlers;
- paper window show/focus code;
- WM_DISPLAYCHANGE/DPI handling.

Required behaviour:
1. Add a Cursor tool if there is none:
   - no drawing tool active;
   - normal arrow cursor;
   - clicking does not draw;
   - available in Screen and Paper modes;
   - visible/active in the tool menu and quick menu.
   Reuse the Linux cursor.png if present in the repository.
2. First Escape or right click while a shape/text/spline/polygon/triangle/line
   still has handles or an unfinished edit:
   - commit/close the handles;
   - keep the selected tool active;
   - return handled.
   A further Escape exits the tool and selects Cursor.
3. Right click, stylus Button 2 or mouse button 2 while the inline text editor
   is open must act like Enter:
   - commit the text;
   - re-enable the mouse;
   - keep the new text handles visible in both Screen and Paper modes.
   Escape still cancels text.  The commit click must not also close handles or
   start the temporary eraser; consume the press and its release.
4. In Paper mode, selecting any tool must bring the Paper window to the front:
   - deiconify/present it;
   - raise it above other applications;
   - focus it;
   - keep the toolbar/floating controls above it.
5. When switching from Paper back to Screen Mode:
   - if the toolbar shows a previously selected tool, actually activate that
     tool in Screen mode; the icon and working tool must agree.
6. On WM_DISPLAYCHANGE, DPI change, monitor change or equivalent:
   - exit the current tool;
   - select Cursor;
   - release tool capture;
   - refresh the cursor and menu active state.
7. Preserve the existing captured-menu/delayed-tool behaviour.

Verification:
- text/arrow/line/spline/polygon/triangle/frame handles;
- first Escape closes handles, second exits to Cursor;
- right click/Button 2 commits text and leaves handles in both modes;
- select a tool while Paper is behind another window;
- switch Paper -> Screen and check the tool actually draws;
- change resolution/DPI with a tool active;
- --uitest, --smoke and --pen-test if pen input changed.

PROMPT 5 - SETTINGS, CONFIG DIRECTORY, RESET AND SHORTCUTS
---------------------------------------------------------
Goal: port the applicable settings/persistence changes without inventing GTK
tabs or Linux-only options.

Inspect src/config.c and the settings/menu commands in src/ui.c and src/main.c.

Required:
1. All Screenator state must live under:
       %APPDATA%\Screenator
   This includes the INI, saved annotations, user hints and any other
   Screenator configuration.  Keep backward compatibility by accepting old
   flat files if any exist.
2. Make the general settings label:
       "Show settings indicator on Floating Icon"
3. Reset Settings must remove the whole %APPDATA%\Screenator directory,
   recursively, after restoring defaults in memory.  Remove any legacy flat
   files too.  Do not leave hints, annotations or old INI files behind.

   - persist in the INI;
   - re-register when settings change;
   - update menu labels;
   - allow disabling a shortcut;
   - keep current defaults compatible with the Windows README.
   If this becomes a large rework, stop and report instead of half-doing it.
5. Do not add Linux Paper Drawing settings for pages, PDFs, continuous
   scrolling or Window mode.
6. Preserve the hidden-hints choice and avoid changing defaults that would
   override saved settings.

Verification:
- config round trip in --uitest;
- restart persistence;
- reset deletes the entire %APPDATA%\Screenator folder;
- hotkey re-registration if implemented;
- README/RELEASE_NOTES updated.

PROMPT 9 - OPTIONAL MAJOR FEATURE: PAPER/PDF PARITY
--------------------------------------------------
Start only if the user explicitly asks for full Linux Paper/PDF parity.

Linux 8.0 Paper/PDF includes:
- Plain/Ruled/Graph/PDF documents;
- multiple pages with insert/delete and page undo/redo;
- continuous scrolling and page navigation;

This is a new subsystem, not a small port.  Before coding, produce a design
with:

- vector export using Cairo PDF;
- UI for pages, paper types and tool bar;
- packaging and licence implications.

Do not write implementation code until the user approves the design and
dependencies.  If not approved, mark the whole item deferred.
